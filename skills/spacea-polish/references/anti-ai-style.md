## 一、用字黑名單（命中就換掉）

### A. 灌水開頭／教科書過渡詞
真人很少在每段開頭端出連接詞，AI 卻很依賴。**禁用**：
- 深入探討、深入挖掘、讓我們深入了解、值得注意的是、重要的是、必須記住
- 首先 / 其次 / 最後 / 然而 / 總而言之（段落結構過於對稱工整也是 AI 味）
- **宣告式「誠實／坦白」開場**：先誠實講一件事 / 老實說 / 坦白說 / 說真的 / 說實話 / 不得不說。真要誠實的人直接講那件事，不會先昭告「我要誠實了」，這是裝真誠的 AI 腔。
- **宣告式「我會說清楚／這篇會告訴你」導引**：我會說清楚 / 我會說明 / 這篇會告訴你 / 本文將介紹 / 接下來會講 / 帶你了解。本來就會把事情講清楚，不用先昭告「我要講了」，直接講內容即可。（註：「我會親自確認那幾則」這種描述**實際動作**的不算，要擋的是宣告「我要解釋」。）
  - **例外：dev-diary 前言第二段的「這篇文章會⋯」不算報幕**（2026-09-08）。那是前言固定結構的一部分——第一段用 `<strong>` 給可被答案引擎抽走的核心事實，第二段用「這篇文章會⋯」宣告涵蓋範圍，讓引擎知道往下有什麼。這是 GEO 需求下的刻意設計，不是填充。例外只限**前言第二段這一處**，內文段落之間照舊禁止報幕。
- **宣告式「把話講在前面」開場**：先把話講在前面 / 話先說在前頭 / 醜話說在前面。要講的重點直接講，不用先預告「我要先講一件事」。
- **宣告式「舉例」開場**：舉個例子 / 舉個實際的例子 / 舉個我的案例 / 舉例來說 / 比如說（放句首當報幕）。要舉例就直接把例子講出來，不用先昭告「我要舉例了」。（註：例子融在句中的「像那條 LINE 流程就…」「我自己一條流程就是這樣：…」不算，要擋的是句首端出「舉例來說：」這種報幕。）
- **宣告式「先交代／先說明」開場**：先交代這個例子是什麼 / 先說明一下 / 先解釋一下背景。要交代就直接交代，不用先昭告「我要交代了」——刪掉這句、後面內容原封不動就是正解。（2026-07-04 實例：「先交代這個例子是什麼。IG 監控工具是…」→ 直接寫「這個 IG 監控工具是…」）
- **換段過場宣告（高頻犯規，使用者明確點名「講過很多次」）**：概念講完，來接真的 / X 都講完了，這段來聊 Y / 設定講完，來看實戰 / 接通之後，真正好玩的才開始 / 好戲在後頭。這種「先總結上一段、再預告下一段」的接縫句沒有資訊量，**段落之間不需要報幕**，直接寫下一段的實際內容即可。
- **宣告式「先講一個…」開場**：先講一個實際情境： / 先說一個例子： / 先講個狀況：。要講情境就直接把情境寫出來，不用先報幕。（2026-08-26 實例：「跟 n8n 比的話，先講一個實際情境：我幫客戶接的 LINE 自動回覆流程…」→「跟 n8n 比的話，我幫客戶接的那條 LINE 自動回覆流程…」）
- **「說到底／說穿了／講白了」當總結報幕**：這幾個詞只是宣告「我要下結論了」，本身不帶資訊，刪掉後那句話一樣完整。（2026-08-26 實例：「Canvas 說到底是把黑盒子式的『AI agent 做事』，變成…」→「Canvas 把黑盒子式的『AI agent 做事』，變成…」）
- **「這裡換一個…走一次」換場報幕**：這裡換一個更貼近的情境走一次 / 這裡拿另一個案例跑一遍。直接接上新情境即可。
- **宣告式「一句話講完／簡單說」開場**：跟 X 的差別一句話講完： / 一句話總結： / 簡單來說 / 簡單講（放句首當報幕）。真要一句話講完就直接把那句話寫出來，不用先宣告「我要濃縮了」。（2026-07-15 實例：「跟編輯器類的差別一句話講完：編輯器是你主導…」→ 直接寫「編輯器是你主導…」）
- **宣告式「先攤開來比一比／先列出來看」開場**：要比較幾個對象，直接進比較內容（表格或句子），不用先宣告「先攤開來比一比」「先列出來看」這種報幕。搭配用的「不是只有 X 在做這件事」這種負面開場句也一起避免，改成直接點名做這件事的幾個對象，正面陳述。（2026-08-24 實例：「『讓你看得到 AI 在做什麼』這件事，不是只有 Canvas 在處理。Claude Code、n8n 各自也有自己的做法，只是切入的角度不一樣，先攤開來比一比：」→ 改成「『讓你看得到 AI 在做什麼』這件事，Claude Code、n8n 各自也有自己的做法，只是切入的角度不一樣：」——保留完整句子與原本資訊量，只刪掉負面開場句「不是只有…在處理」跟句尾「先…比一比」的報幕，不是整句砍短。）
- **自我背書句**（2026-09-11 使用者點名「好噁的 AI 語言」）：「每一條的團費都是從行程頁直接抄下來的」「以上資料皆經查證」「價格都是我一家一家查的」。這是在替自己的可信度打廣告，真人寫文章不會停下來宣告「我有查」。**改法**：整句刪掉，可信度靠內文的具體數字自己撐。
- **改法**：直接講下一件事，不要端連接詞、不要宣告開場、不要在換段時總結＋預告；段落長短故意做不對稱。

### B. 浮誇強調詞（把小事講得驚天動地）
**禁用**：至關重要、關鍵的、樞紐的、不可磨滅（「留下了不可磨滅的印記」）、顯著的、凸顯了 / 強調了（拿抽象事實當主詞）。
- **給抽象事物套虛無的感官／情緒形容詞**：發現「有點刺眼」、數字「觸目驚心」、結果「血淋淋」、「發人深省」「耐人尋味」。發現不會刺眼、數字不會觸目，這是不符現實的硬套，最常見。
- **改法**：用具體數字或後果代替形容詞，「省 40 分鐘」勝過「至關重要」、「同事不用加班到八點」勝過「顯著提升」；直接講事實，「將近九成客戶一年只買一次」本身就夠力，不用再加「刺眼」。

### C. 社群情緒假詞（裝熟、空洞）
**禁用**：穩、撐、懂（懂的都懂 / 穩了 / 撐住）、接住 / 不繞 / 很現實（「這次換我來接住你的情緒」）、其實 / 很清楚 / 很簡單（當語氣助詞濫用）。
- **技術社群黑話**：踩坑 / 踩雷 / 避坑 / 填坑 / 入坑（2026-09-07 使用者點名「踩坑是禁詞」）。這類詞是簡中技術社群用語，繁中讀者不會這樣講，寫進標題或內文都很出戲。
  **改法**：直接講發生什麼事——「新手最常卡住的五件事」「這幾件事最常讓新手卡住」「真正卡住我的幾個問題」，不要用坑當比喻。
- **改法**：講具體場景與動作，不裝感性。

### D. 經典 AI 句型（抓包率最高）
**禁用**：
- 「這不是……而是……」（工整反轉金句）
- 「不僅是……更是……」（無限昇華意義）
- **「正面敘述，不是……」的否定收尾**：例如「穩定器和三腳架怎麼挑，不是兩個都要買」——即使沒有接「而是」，這種「先講一件事、再用『不是』甩一個否定」的收尾同樣是反轉句骨架。**改法**：把要講的判斷正面講完（「穩定器和三腳架先挑一個就好」）。
- 「從……到……」假範圍（跨度過大、邏輯斷裂，如「從宇宙起源到現代行銷」）
- **破折號（——）一律不用**（2026-09-09 統一）：句尾補充是被網友公認 99% 秒判 AI 的符號。要補一句白話解釋、附註或轉折時**一律改用括號或句號斷句**。dev-diary 舊版寫的「用括號或破折號附白話解釋」以本條為準，破折號那個選項作廢。**唯一例外**：threads-diary 編號列點的「1. 短標 — 說明」那個分隔用的「—」是使用者既定風格，不在此限。
- 三段式排比（連列三個形容詞 / 「願妳勇敢、願妳溫柔、願妳永遠是自己」）
- 僵化結尾（In conclusion / Overall / 綜上所述）
- **殘句標語**：H2 或重點句寫成「問句？＋聳動斷句」，句子不完整又沒吃關鍵字（如「群發 EDM 為什麼都沒人打開？因為你對 2 萬人發同一封」——「發同一封」什麼沒講完）。真人寫標題會把句子收完整。
- **逗號拼接的鋪陳→翻轉句**：H2 或重點句用兩三個逗號把「主題、鋪陳、punchline」黏成一句，堆出節奏感（如「你做的網站，AI 一直沒看過，不貼截圖它只能用猜的」）。這種多短句拼接製造「揭曉感」的寫法是 AI 常見句型，真人寫標題會直接寫成一句主謂賓完整的句子。**改法**：砍成一句話講完一件事（改成「一般的 AI 看不到你的網站長什麼樣子」），不用鋪陳再翻轉；同時檢查主詞夠不夠精準——文章主角是特定工具時，泛稱的「AI」容易讓讀者誤會在講主角本身，要寫清楚是「一般的 AI」還是別的對照組（2026-09-04 使用者點名）。
- **懸念式標題「…長什麼樣」**（2026-07-15 使用者點名「AI 都喜歡這種不明所以的標題」）：「用了半年之後，我的主力組合長什麼樣」這種吊胃口標題不講內容。改成直接說要分享什麼（「跟大家分享我實戰在用的 AI 寫程式工具搭配」），標題吃關鍵字。
- **標題「先搞懂／先了解…」開頭**（2026-07-15 使用者點名）：H2 用「先搞懂這 10 款工具的分工」是對讀者下指令的報幕腔。直接講主題（「10 款 AI Coding 工具分工解析」），不要叫讀者「先」做什麼。
- **憑空宣告「是真的／不是假的」**：前文沒人質疑、沒設下「這是不是真的？」的問句，卻突然斷言「這兩個風險都是真的」「這擔心不是多餘的」「這問題確實存在」。AI 愛先替讀者立一個假想質疑、再出面證實，真人不會對沒被問的事自證為真。
- **「閃得掉／躲得掉／逃不掉」這類裝順口語**：用一個看似生動的動詞包裝「可以避免」（如「這兩個風險都閃得掉」「這問題躲不過」），讀起來像口語其實沒人這樣講，是 AI 硬找俏皮動詞的痕跡。**改法**：多半整句直接刪掉、進入下一句講具體做法即可；真要講就用平實的「都能避開／可以避免」。
- **冒號＋聳動斷言式標題**：H2 寫成「主題：它們根本不在同一個賽道」這種「前半正常、冒號後接一句聳動斷言」的句式（2026-07-13 被點名太 AI）。「根本不在同一個賽道」「根本不是一回事」這類斷言只有音量沒有資訊。**改法**：冒號後面講具體差異或讀者利益（「它們適合不同的族群」）。
- **縮略口號式標題**：H2／重點句把準則壓成沒有主詞動詞的斷句口號（「不自動推、repo 別養肥」，2026-07-16 被點名講不清楚、太 AI）。**改法**：寫成完整句的準則——「推之前先本機測試、repo 盡量保持乾淨」，讀者不用猜縮略字在指什麼。
- **「出手」當「操作」用的武俠腔**：「人唯一出手的一次」「只在最前面出手」這種把日常操作包成武俠動作的寫法，同屬硬找俏皮動詞（2026-07-04 被點名太 AI）。**改法**：換平實的「動手／要人操作」——「全程只有這步要動手」。
- **改法**：用「而」＋具體脈絡（「她哀悼的不是過去，**而是**回不去的童年」）；一句話只講一件事；H2／重點句寫成**完整句子**並把關鍵字鑲進去（「…因為你把同一封信發給了所有客戶」）；要講的事直接講，過渡句寧可刪掉也不要硬塞俏皮動詞。

### E. 空洞、模糊、格式殘留
**禁用**：空洞讚美（燈塔 / 見證 / 文化遺產中心）、模糊歸因（「批評者認為……」不指名）、Markdown 殘留（`##`、`**` 跑進正文）、異常工整的條列與大寫標題。
- **改法**：歸因要指名；讚美換成可驗證的事實。

### F. 抽象化、缺乏錨點
**禁用**：
- 概念名詞化：自我的探索、認同感的建構、內在小孩的療癒、效率的提升
- 缺乏錨點：某個午後、在忙碌的城市裡、認識一個朋友她、大幅提升、許多企業
- **改法**：名詞化換動詞口語（「自我的探索」→「找自己」；「效率的提升」→「少做一堆白工」）；抽象錨點換真實時間／地點／人名／數字。

## 二、EEAT 具體化（正面準則：真實 > 宏觀）

AI 味的根源是「統計上最安全＝空泛宏觀」。人味＝**活過的證據**。每篇都要做到：

1. **具體錨點取代概念**：真實的時間、地點、數字、客戶情境。
   - ❌「自動化能大幅提升行銷團隊效率」
   - ⭕「上週幫一個賣保健食品的客戶接 n8n，他原本每天早上花 40 分鐘把 GA4 數字貼進 Excel，現在 8 點打開 LINE 報表已經躺在那」
2. **動詞推動，不要堆名詞**：好句子靠動詞，名詞一多就軟綿綿（AI 受學術摘要訓練資料影響愛堆名詞）。
3. **節奏不對稱**：真人句子有長有短，不會每段一樣長、每組都排比。
4. **看得到「誰」，不是「人們」**：寫得出具體的人與動作，而不是抽象群體。
5. **真實，不是編造**：具體錨點必須來自真實素材（拉 material_log）。不能為了具體而編戲劇化假故事；匿名化的客戶情境要標示「示意」。（呼應 feedback_no_fake_anecdotes）

### 三個交付前檢驗法
- **能不能拍成電影？** 有溫度、氣味、畫面、動作才是真寫作；拍不出來＝AI 味。
- **唸出聲音會不會像作文範本？** 太順、太對稱、太工整 → 重寫。
- **看得到「誰」嗎？** 寫得出阿芳穿藍外套喝冰美式，而不是「一位朋友」。

## 三、標題與節奏的 AI 味（長文 skill 共用）

用字沒命中黑名單，不代表沒有 AI 味。**最容易露餡的是標題與段落節奏**，這兩件事腳本抓不到，只能人工唸過。

### 標題：短句不等於冷標籤
短句是**完整的短句子**，不是把句子壓成名詞堆。兩者差在讀起來是不是一句話：

| | 寫法 | 例 |
|---|---|---|
| ⭕ 短句 | 短、完整、有動詞、吃得到關鍵字 | 「Mac 如何安裝 Claude Code」「執行原則擋住安裝指令怎麼辦」 |
| ❌ 冷標籤 | 名詞堆疊，沒有動詞，像目錄 | 「Mac 安裝說明」「Instagram 發文 API 串接說明」「Token 過期處理機制」 |
| ❌ 縮略口號 | 砍到沒主詞動詞，讀者要猜 | 「不自動推、repo 別養肥」 |

### 標題不要硬塞比喻或擬人化
真人寫標題用平實口語，不賣弄文采。**擬人化與做作比喻是最典型的 AI 腔**：「幫 Token 續命」「API 的脾氣不一樣」「資料在管線裡旅行」這種把工具當人、硬湊比喻的句子一律禁用。直接說「Token 會過期、要定期更新」就好。寧可樸素也不要做作。

| 技巧 | AI 腔（壞） | 平實（好） |
|------|------|------|
| 用後果說人話 | 登入 Token 未加密處理 | 後台登入的 Token 沒加密，等於沒鎖 |
| 疑問帶關鍵字 | 暴力破解防護機制 | 後台登入猜錯不會被鎖，暴力破解就有機可乘 |
| 取捨／口語 | 多平台發文 API 串接架構 | 為什麼我沒用 Buffer，改自己用 n8n 串 API 發文 |
| 別硬湊比喻 | 幫 Token 續命的自動化機制 | 自己串 API 最麻煩的一件事：Token 會過期 |

### 節奏：去工整化
通篇最大的 AI 感來自「太工整、太平均」，每個段落都走『定義→解釋→結論』同一個模子，讀到第三四個就有教科書感。打散手法：

1. 標題問句／陳述句／觀點句**交錯**，不要連續好幾個都問句
2. 部分段落直接用**情境或反問開頭、不先下定義**
3. **比喻挑最重要的一兩個用力講**，其餘直接說，全部都套比喻反而沒重點
4. 收尾別用慣性套句（如「真正值得記住的是…」），改用作者口吻自然收束
5. 多用**口語與具體畫面**（「傻傻把每句都存起來」勝過抽象敘述）
6. **適時用列點打破整片純段落**，讓版面有呼吸感（但別每段都列，一篇抓 1～3 處即可）

### 腳本 0 命中 ≠ 通過
`check-ai-style.mjs` 只抓得到黑名單字詞，抓不到「讀起來像 AI 硬湊的順口語」。實例：「送出前，人先看一眼」沒命中任何黑名單詞，但真人不會這樣講話，後來改成「送出前還是要人看過」。**標題寫完要唸出聲音**確認像不像真人會講的話，不是只看腳本過不過。

## 四、各 skill 的差異套用

- **dev-diary / qa-article（長文）**：全部適用。重點在 A/B/D/E/F 與 EEAT 具體錨點；破折號、三段排比、「這不是…而是…」尤其要清。
- **threads-diary（社群口語）**：C（情緒假詞：穩／撐／懂／接住）與 D（這不是…而是…、破折號）是重災區，最優先擋；本來就走口語自嘲，更要避免裝感性。
- **linkedin-post（專業）**：B（浮誇強調詞）與 E（空洞讚美 / 模糊歸因）最該擋；專業感靠具體案例與數字，不靠形容詞。


## 六、版面：段落不要擠成一坨

**單一 `<p>` 超過 200 字（中文）就要處理。** 這不是排版問題，是結構問題：
會寫成 200 字以上的一坨，通常代表那段裡塞了本來就該分開的東西。

依內容性質選處理方式，不要只是硬斷句：

- **並列的項目**（模式、方案、步驟、工具、選項）→ 改表格或列點。
  並列資訊寫成散文，讀者得自己在腦中重建那張表。
  實例（2026-09-08，claude-code-tutorial）：六種權限模式塞進一段 420 字，
  拆成「導言 111 字＋六列表格＋建議 200 字」後才讀得下去。
- **兩個以上獨立論點** → 拆成兩段。
- **換了主題** → 拆 H3。

另外，**一個 H2 底下連續 4 段以上沒有小標、表格或圖**，讀者會失去落點，考慮拆 H3。

參考值：一篇正常的文章段落平均約 110 字，200 字是上限不是目標。
